01

RAG와 Fine-tuning 차이

  • RAG는 질문할 때마다 외부 문서를 검색해 Context로 붙입니다.
  • Fine-tuning은 원하는 질문·답변 패턴을 반복 학습해 모델의 응답 방식과 전문성을 조정합니다.
  • 이 강의는 전체 4B 모델을 모두 갱신하지 않고 작은 LoRA adapter만 학습합니다.
  • 학습 데이터가 잘못되면 틀린 API도 그대로 학습하므로 양보다 검증 품질이 중요합니다.

03

학습 데이터 만들기

JSON은 반드시 최상위 list이고, 각 항목에 문자열 input과 output이 있어야 합니다.

[
  {
    "input": "배터리 전압이랑 잔량 좀 확인해줘.",
    "output": "from pinkylib import Battery\n..."
  },
  {
    "input": "앞으로 1초 이동해.",
    "output": "from pinkylib import Motor\n..."
  }
]
  • 단순 제어·센서·복합 로직·로봇 설명을 골고루 포함합니다.
  • 문서에 정의된 class와 method만 사용하고 없는 API를 만들지 않습니다.
  • 하드웨어 코드는 try-finally와 close()로 자원을 해제합니다.
  • JSON 문법과 모든 Python output을 별도로 검사합니다.

04

train_pinky.py 단계별 복사

1 · MODEL

Import와 4bit 모델 설정

from unsloth import FastLanguageModel
import torch
from datasets import Dataset
import json
from trl import SFTTrainer
from transformers import TrainingArguments

max_seq_length = 2048
dtype = None
load_in_4bit = True
input_json = "pinky_finetune_data.json"
model_name = "unsloth/Qwen3-4B-unsloth-bnb-4bit"

model, tokenizer = FastLanguageModel.from_pretrained(
    model_name=model_name,
    max_seq_length=max_seq_length,
    dtype=dtype,
    load_in_4bit=load_in_4bit,
)
2 · LoRA

학습할 adapter 지정

model = FastLanguageModel.get_peft_model(
    model,
    r=16,
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj",
                    "gate_proj", "up_proj", "down_proj"],
    lora_alpha=16,
    lora_dropout=0,
    bias="none",
    use_gradient_checkpointing="unsloth",
    random_state=3407,
    use_rslora=False,
    loftq_config=None,
)
3 · DATA

JSON을 Alpaca format으로 변환

with open(input_json, "r", encoding="utf-8") as f:
    data = json.load(f)

def format_prompt(example):
    input_text = example["input"]
    output_text = example["output"]
    text = f"""### Instruction:
{system_prompt}

{input_text}

### Response:
{output_text}"""
    return text + tokenizer.eos_token

formatted_data = [{"text": format_prompt(item)} for item in data]
dataset = Dataset.from_list(formatted_data)
4 · TRAIN

SFTTrainer 학습 설정

trainer = SFTTrainer(
    model=model,
    tokenizer=tokenizer,
    train_dataset=dataset,
    dataset_text_field="text",
    max_seq_length=max_seq_length,
    dataset_num_proc=2,
    args=TrainingArguments(
        per_device_train_batch_size=1,
        gradient_accumulation_steps=4,
        warmup_steps=10,
        num_train_epochs=10,
        learning_rate=2e-4,
        fp16=not torch.cuda.is_bf16_supported(),
        bf16=torch.cuda.is_bf16_supported(),
        logging_steps=1,
        optim="adamw_8bit",
        weight_decay=0.01,
        lr_scheduler_type="linear",
        seed=3407,
        output_dir="pinky_outputs",
    ),
)
trainer.train()
5 · GGUF

LoRA merge와 Q4_K_M 저장

model.save_pretrained_gguf(
    "pinky_model",
    tokenizer,
    quantization_method="q4_k_m",
)

FIX

문제 해결과 안전 검증

강의의 GGUF merge 오류: Bad in-place call: input tensor size ... should match는 모델·Unsloth·Transformers·GGUF 변환 조합 불일치에서 발생할 수 있습니다. 학습 결과를 지우기 전에 adapter checkpoint를 보존하고 version 조합을 기록합니다.
  • CUDA OOM: 다른 GPU process 종료 → sequence 길이 축소 → batch size 유지 → gradient checkpointing 확인 순서로 봅니다.
  • W&B prompt: 결과를 upload하지 않을 경우 선택지 3을 입력합니다.
  • JSON 오류: python3 -m json.tool로 comma·quote·newline escape를 검사합니다.
  • API가 틀림: 학습 데이터 output을 pinky_library.md와 대조합니다.
  • GGUF가 없음: 현재 폴더뿐 아니라 pinky_model 아래도 확인합니다.
  • 모델 cache: 기본 위치는 ~/.cache/huggingface/hub입니다.
  • 생성된 로봇 코드는 바로 실행하지 말고 사람 검토, 속도·시간 제한, try-finally, close()를 확인합니다.
