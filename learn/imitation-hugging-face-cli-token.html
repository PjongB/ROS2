01

Hugging Face Hub와 Access Token

Hub는 모델·데이터셋·애플리케이션을 버전 관리하고 공유하는 공간입니다. Access Token은 비밀번호 대신 CLI와 API를 인증하는 키이며, LeRobot의 업로드 대상은 username/repository-name 형식으로 식별합니다.

권한읽기쓰기용도
Fine-grained선택선택특정 저장소로 범위 제한
Read가능불가비공개 자료 다운로드
Write가능가능강의의 데이터셋·모델 업로드
02

계정과 토큰 생성

  1. huggingface.co에서 계정을 만들고 이메일 인증을 완료합니다.
  2. 프로필 → Settings → Access Tokens → Create new token으로 이동합니다.
  3. 용도를 알 수 있는 이름을 붙이고 강의 업로드용 Write 권한을 선택합니다.
  4. 생성 직후 한 번만 표시되는 hf_... 값을 안전한 비밀 저장소에 보관합니다.
토큰은 비밀번호입니다. 명령 기록, 화면 캡처, Git 저장소, 노션 본문, 메신저에 실제 값을 남기지 마세요. 노출되면 즉시 Revoke하고 새 토큰을 만듭니다.
03

CLI 인증

셸 변수에 실제 토큰을 넣고 로그인합니다. 아래 자리표시자를 토큰 그대로 커밋하거나 공유하지 않습니다.

source ~/venv/il/bin/activate
cd ~/il_ws/src/lerobot

export HUGGINGFACE_TOKEN='hf_your_write_token'
hf auth login --token "${HUGGINGFACE_TOKEN}" --add-to-git-credential
hf auth whoami
강의의 credential.helper store: 편리하지만 ~/.git-credentials에 인증 정보를 평문으로 저장할 수 있습니다. 개인 장비에서만 사용하고, 공용 PC에서는 OS credential manager 또는 세션 로그인 방식을 사용하세요.

Token is valid (permission: write)와 로그인 성공 메시지가 나오면 인증이 완료된 것입니다.

04

사용자명을 HF_USER로 저장

HF_USER=$(hf auth whoami | head -n 1 | sed 's/\x1b\[[0-9;]*m//g' | awk -F': ' '{print $2}' | xargs)
echo "$HF_USER"

이후 ${HF_USER}/record-test, ${HF_USER}/omx_act_policy처럼 본인 계정에 맞는 저장소 경로를 재사용할 수 있습니다. 새 터미널에서는 변수를 다시 설정해야 합니다.

05

인증 파일과 로그아웃

항목의미
~/.cache/huggingface/stored_tokensHF CLI가 관리하는 저장 토큰
~/.cache/huggingface/token현재 활성 토큰
~/.git-credentialsstore helper 사용 시 Git 인증 정보
hf auth logout

공용 장비 사용 후에는 로그아웃하고, Hugging Face 웹 설정에서 해당 토큰도 폐기합니다.

전체 실행 순서

source ~/venv/il/bin/activate
cd ~/il_ws/src/lerobot

# 실제 값은 안전한 방법으로 현재 shell에만 입력
export HUGGINGFACE_TOKEN='hf_your_write_token'
hf auth login --token "${HUGGINGFACE_TOKEN}" --add-to-git-credential
hf auth whoami

HF_USER=$(hf auth whoami | head -n 1 | sed 's/\x1b\[[0-9;]*m//g' | awk -F': ' '{print $2}' | xargs)
echo "$HF_USER"
unset HUGGINGFACE_TOKEN
