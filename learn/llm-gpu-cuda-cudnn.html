GPU·NVIDIA 드라이버·CUDA·cuDNN 설정

PinkyPro에 LLM·AI 기능을 연결하기 전, Ubuntu PC의 NVIDIA GPU를 확인하고 드라이버부터 CUDA, cuDNN, Python framework까지 순서대로 검증합니다.

한 줄 정리GPU stack은 hardware → driver → CUDA Toolkit → cuDNN → framework 순서로 쌓이며, 각 단계의 버전 호환성과 검증 결과를 확인한 뒤 다음으로 넘어가야 합니다.
MAP

GPU 실행 환경의 층

GPUNVIDIA hardware
DriverOS와 GPU 연결
CUDA·cuDNN연산·DNN library
FrameworkTensorFlow·LLM

아래 계층이 동작하지 않으면 위 계층을 재설치해도 해결되지 않습니다. 항상 아래에서 위로 진단합니다.

01

GPU와 PCI 장치 확인

lspci | grep -Ei 'vga|3d|display'
lspci | grep -i nvidia
lspci -nnk | grep -A3 -Ei 'vga|3d|display'

노트북은 내장 GPU와 NVIDIA 외장 GPU가 함께 표시될 수 있습니다. 장치명과 현재 사용 중인 kernel driver를 기록합니다.

02

NVIDIA 드라이버 확인·설치

# 이미 설치되어 있는지 확인
nvidia-smi

# Ubuntu가 제공하는 후보와 권장 항목 확인
ubuntu-drivers devices

# 권장 드라이버 자동 설치
sudo ubuntu-drivers autoinstall
sudo reboot

재부팅 후 nvidia-smi가 GPU, driver version, process 정보를 보여주는지 확인합니다. 강의자료는 후보 중 recommended 항목을 권장합니다.

주의: 기존 NVIDIA 패키지 전체 삭제는 복구 작업입니다. 정상 설치에 먼저 실행하지 말고, 문제가 확인된 경우에만 설치 기록과 복구 방법을 확보한 뒤 진행하세요.
03

버전 호환 조합 결정

CUDA와 cuDNN은 원하는 최신 버전을 무조건 고르는 것이 아니라 GPU driver·Ubuntu·Python framework가 함께 지원하는 조합을 선택합니다.

  • NVIDIA cuDNN Support Matrix에서 CUDA·driver·hardware 조건을 확인합니다.
  • CUDA Toolkit Archive에서 선택한 버전의 Ubuntu 설치 명령을 생성합니다.
  • 강의자료의 예시는 CUDA Toolkit 13.1이지만, 실제 설치 시점의 framework 지원 여부를 다시 확인합니다.
04

CUDA Toolkit 설치 흐름

  1. CUDA Archive에서 OS, architecture, distribution, version, installer type을 고릅니다.
  2. NVIDIA가 생성한 명령으로 cuda-keyring 패키지를 다운로드합니다.
  3. sudo dpkg -i <cuda-keyring.deb>로 저장소와 인증 키를 등록합니다.
  4. sudo apt update로 package 목록을 갱신합니다.
  5. 선택한 버전의 toolkit package를 설치합니다.
# 예: 강의자료가 선택한 버전
sudo apt install cuda-toolkit-13-1

다운로드 URL과 keyring 파일명은 Ubuntu 버전·architecture에 따라 달라지므로 NVIDIA 페이지가 생성한 값을 그대로 사용합니다.

05

CUDA 경로 설정

echo 'export PATH=/usr/local/cuda-13.1/bin:$PATH' >> ~/.bashrc
echo 'export LD_LIBRARY_PATH=/usr/local/cuda-13.1/lib64${LD_LIBRARY_PATH:+:${LD_LIBRARY_PATH}}' >> ~/.bashrc
source ~/.bashrc

nvcc --version
nvidia-smi

다른 CUDA 버전을 골랐다면 cuda-13.1을 실제 설치 경로로 바꿉니다. 같은 export 줄을 반복 추가하지 않도록 grep CUDA ~/.bashrc로 먼저 확인합니다.

06

cuDNN 설치

  1. cuDNN Archive에서 CUDA와 맞는 release를 선택합니다.
  2. Ubuntu용 local repository .deb를 다운로드합니다.
  3. dpkg -i로 local repository를 등록합니다.
  4. repository key를 system keyring 위치에 복사합니다.
  5. sudo apt update 후 안내된 cuDNN package를 설치합니다.

구체적인 파일명과 package 이름은 선택한 cuDNN release 화면의 명령을 기준으로 합니다.

07

Python 가상환경에서 테스트 준비

python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install tensorflow

시스템 Python과 프로젝트 dependency를 분리합니다. framework가 요구하는 Python·CUDA·cuDNN 버전도 설치 전에 확인합니다.

08

TensorFlow GPU 인식 확인

python -c "import tensorflow as tf; print(tf.config.list_physical_devices('GPU'))"
  • GPU device 목록이 나오면 framework까지 연결된 상태입니다.
  • 빈 배열이면 nvidia-smi → nvcc --version → framework log 순으로 원인을 좁힙니다.
  • LLM package를 설치하기 전에 이 최소 테스트 결과를 기록해 기준 상태를 만듭니다.
09

증상별 문제 해결

  • lspci에도 NVIDIA가 없음: BIOS·hardware 인식부터 확인합니다.
  • nvidia-smi 실패: driver 설치 상태, kernel module, Secure Boot를 확인합니다.
  • nvcc 없음: toolkit 설치와 PATH를 확인합니다.
  • shared library 오류: cuDNN package와 LD_LIBRARY_PATH를 확인합니다.
  • TensorFlow GPU 0개: framework가 현재 CUDA·cuDNN 조합을 지원하는지 확인합니다.

권장 설치·검증 순서

# 1. Hardware
lspci | grep -i nvidia

# 2. Driver
ubuntu-drivers devices
nvidia-smi

# 3. Compatibility matrix에서 버전 결정
# 4. NVIDIA 안내대로 CUDA repository와 toolkit 설치
# 5. CUDA
nvcc --version

# 6. 호환되는 cuDNN 설치
# 7. Python 가상환경과 framework 설치
# 8. End-to-end 확인
python -c "import tensorflow as tf; print(tf.config.list_physical_devices('GPU'))"

완료 체크리스트

  1. GPU model과 Ubuntu version을 기록했습니다.
  2. nvidia-smi가 정상 실행됩니다.
  3. 호환표에서 driver·CUDA·cuDNN·framework 조합을 정했습니다.
  4. nvcc --version으로 CUDA를 확인했습니다.
  5. 가상환경에서 TensorFlow가 GPU를 인식합니다.
  6. 설치 명령과 version을 재현 가능하게 기록했습니다.
