01

Gazebo 기본과 버전

원본 목차 1–2

  • ROS 2 Jazzy에서는 최신 Gazebo 계열과 맞는 패키지·브리지를 사용해야 합니다.
  • ROS 배포판과 Gazebo 버전의 호환 조합을 먼저 확인합니다.
  • 가상 머신에서는 3D 가속과 그래픽 성능에 따라 실행이 느리거나 화면이 표시되지 않을 수 있습니다.
02

Pinky Gazebo 패키지 구성

원본 목차 2.4–2.5

  • Description 패키지는 로봇 구조를, Gazebo 패키지는 world·시뮬레이션 실행·플러그인을 담당합니다.
  • launch에는 실행 구성을, urdf에는 Gazebo 전용 Xacro 설정을 둡니다.
  • 패키지 리소스는 CMakeLists.txt 설치 규칙에 포함되어야 실행 시 찾을 수 있습니다.
03

launch_sim.launch.xml 실행 흐름

원본 목차 3

  • Gazebo 서버와 클라이언트를 시작하고 원하는 world를 불러옵니다.
  • Description의 upload launch가 robot_description을 발행하면 spawn 과정이 그 모델을 Gazebo에 생성합니다.
  • ROS–Gazebo bridge와 카메라 bridge를 함께 실행해 양쪽 통신을 연결합니다.
04

pinky_gz.launch.xacro

원본 목차 4

  • Differential drive에는 좌우 바퀴 joint, 바퀴 간 거리와 반지름 설정이 필요합니다.
  • gz_ros2_control을 쓰면 ROS 2 controller가 구동을 맡고, 쓰지 않으면 Gazebo diff-drive plugin을 사용할 수 있습니다.
  • 마찰 계수와 바퀴의 물리 특성이 잘못되면 미끄러지거나 움직임이 불안정해집니다.
05

센서와 ROS–Gazebo Bridge

원본 목차 3.8–3.9·4.7–4.9

  • Gazebo transport와 ROS 2 topic은 별개이므로 ros_gz_bridge가 메시지를 변환합니다.
  • LiDAR, 두 대의 카메라, IMU마다 topic 이름·메시지 형식·방향을 맞춰야 합니다.
  • RViz에서 데이터가 보이지 않으면 bridge 실행 여부, topic, QoS와 frame_id를 확인합니다.
06

실행하고 RViz에서 확인

원본 목차 5

  • 시뮬레이션을 실행한 뒤 RViz Fixed Frame과 RobotModel을 먼저 확인합니다.
  • LaserScan과 Image display를 추가해 LiDAR 및 두 카메라 영상을 확인합니다.
  • 키보드 teleop으로 /cmd_vel을 발행하고 로봇이 정상적으로 이동하는지 시험합니다.

터미널 실행 순서

source /opt/ros/jazzy/setup.bash
source ~/pinky/install/local_setup.bash

# Gazebo 시뮬레이션 실행
ros2 launch pinky_gz_sim launch_sim.launch.xml

# RViz 실행
rviz2

# 키보드로 로봇 조작
ros2 run teleop_twist_keyboard teleop_twist_keyboard
