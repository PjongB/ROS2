01

실물 TurtleBot3 실행과 관찰 순서

# 터미널 A · SBC에 SSH 접속 후 bringup
ssh <USER>@<ROBOT_IP>
source /opt/ros/jazzy/setup.bash
source ~/turtlebot3_ws/install/setup.bash
export ROS_DOMAIN_ID=30
export TURTLEBOT3_MODEL=burger
ros2 launch turtlebot3_bringup robot.launch.py

# 터미널 B · PC에서 저장 지도 기반 Nav2
source /opt/ros/jazzy/setup.bash
source ~/turtlebot3_ws/install/setup.bash
export ROS_DOMAIN_ID=30
export TURTLEBOT3_MODEL=burger
ros2 launch turtlebot3_navigation2 navigation2.launch.py \
  map:=$HOME/turtlemap.yaml

# 터미널 C · 실제 노드 확인
ros2 node list
ros2 param list /controller_server
ros2 param list /local_costmap/local_costmap
ros2 param list /global_costmap/global_costmap
ros2 param list /amcl

30과 burger는 예시입니다. 실제 PC·SBC 및 보유 모델 값으로 통일합니다.

02

RQT에서 변경하는 순서

source /opt/ros/jazzy/setup.bash
source ~/turtlebot3_ws/install/setup.bash
export ROS_DOMAIN_ID=30
export TURTLEBOT3_MODEL=burger
rqt
  1. Plugins → Configuration → Dynamic Reconfigure를 엽니다.
  2. 대상 노드를 고르고 현재값을 기록합니다.
  3. 한 항목을 작은 폭으로 바꿉니다.
  4. ros2 param get으로 실제 적용을 확인합니다.
  5. RViz의 Global·Local Costmap과 실물 주행을 비교합니다.
ros2 param get /global_costmap/global_costmap \
  inflation_layer.inflation_radius

04

모델·실물·Gazebo 구분

구분확인할 것잘못됐을 때
Burger / Wafflefootprint, 속도, 회전 특성가짜 충돌·통로 오판
실물OpenCR·odometry·LiDAR frame제어 불응·위치 불안정
Gazebouse_sim_time:=True, /clockTF 시간 오류
PC↔SBCDomain ID·network·동일 모델노드가 일부만 보임
튜닝 전에: /scan, /odom, /tf, /cmd_vel과 Map·Scan 정합을 먼저 확인합니다.
05

백업과 영구 반영

mkdir -p ~/robot_param_backup
ros2 param dump /controller_server \
  --output-dir ~/robot_param_backup
ros2 param dump /local_costmap/local_costmap \
  --output-dir ~/robot_param_backup
ros2 pkg prefix --share turtlebot3_navigation2

설치 공간을 직접 고치면 다음 빌드 때 사라질 수 있습니다. 소스 워크스페이스의 실제 Nav2 YAML에 검증된 값만 반영합니다.

✓

완료 체크리스트

  1. PC와 SBC의 Domain ID·모델 값이 같습니다.
  2. 실제 노드와 plugin namespace를 확인했습니다.
  3. 변경 전 값을 저장했습니다.
  4. 한 항목씩 바꾸고 적용값을 재조회했습니다.
  5. 검증된 값만 YAML에 반영했습니다.
