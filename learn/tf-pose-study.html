2. 좌표계(Frame)와 TF

좌표계는 위치와 방향을 표현하는 기준축이다. 로봇 시스템에는 world, base_link, 카메라, 라이다처럼 여러 좌표계가 동시에 존재한다.

고정 기준 좌표계
→Transform
moving_frame자식 프레임
원 위를 이동
용어의미
Frame위치와 방향을 측정하는 기준 좌표계

tf2시간에 따라 변하는 TF 트리를 저장하고 조회하는 라이브러리
Broadcaster좌표계 변환을 지속적으로 발행하는 주체
Listener발행된 변환을 받아 저장·조회하는 주체
읽는 법: world → moving_frame은 “moving_frame의 위치와 자세를 world 기준으로 설명한다”는 뜻이다.

3. TransformStamped 메시지 해부

동적 TF 한 개는 geometry_msgs/msg/TransformStamped 메시지에 담긴다.

transform = TransformStamped()
transform.header.stamp = self.get_clock().now().to_msg()
transform.header.frame_id = 'world'
transform.child_frame_id = 'moving_frame'

transform.transform.translation.x = x
transform.transform.translation.y = y
transform.transform.translation.z = 0.0

transform.transform.rotation.x = qx
transform.transform.rotation.y = qy
transform.transform.rotation.z = qz
transform.transform.rotation.w = qw
필드역할
header.stamp이 변환이 유효한 ROS 시간
header.frame_id부모 프레임 이름: world
child_frame_id자식 프레임 이름: moving_frame
translation부모 기준 자식의 위치 x, y, z
rotation부모 기준 자식의 Quaternion 자세 x, y, z, w
시간이 중요한 이유: TF는 시간에 따라 변한다. 현재 시간 없이 발행하거나 프레임마다 시간이 크게 다르면 tf2가 원하는 시점의 변환을 계산하지 못할 수 있다.

4. my_tf_1: 원운동 위치만 발행

0.1초마다 각도 값을 0.05 rad씩 증가시키고 삼각함수로 원 위의 좌표를 계산한다.

x = 2 cos(θ)   ·   y = 2 sin(θ)   ·   z = 0
  • 반지름: 2m
  • 중심: (0, 0)
  • 운동 평면: world의 xy 평면
  • 타이머 주기: 0.1초, 10Hz
class MyTfBroadcaster(Node):
    def __init__(self):
        super().__init__('my_tf_broadcaster')
        self.broadcaster = TransformBroadcaster(self)
        self.timer = self.create_timer(0.1, self.timer_callback)
        self.angle = 0.0

    def timer_callback(self):
        self.angle += 0.05

        transform = TransformStamped()
        transform.header.stamp = self.get_clock().now().to_msg()
        transform.header.frame_id = 'world'
        transform.child_frame_id = 'moving_frame'

        transform.transform.translation.x = 2.0 * math.cos(self.angle)
        transform.transform.translation.y = 2.0 * math.sin(self.angle)
        transform.transform.translation.z = 0.0

        transform.transform.rotation.w = 1.0
        self.broadcaster.sendTransform(transform)
단위 Quaternion: 회전이 없더라도 (x,y,z,w)=(0,0,0,1)을 지정한다. 모두 0인 Quaternion은 유효한 회전이 아니다.

5. 자세 표현: Euler에서 Quaternion까지

표현장점주의점
Euler
roll, pitch, yaw		사람이 직관적으로 이해하기 쉽다.회전 순서에 따라 결과가 달라지고 Gimbal Lock이 생길 수 있다.
Quaternion
x, y, z, w		특이점 없이 회전 보간과 합성에 적합하다.네 숫자의 의미를 직관적으로 읽기 어렵고 정규화가 필요하다.

Roll, Pitch, Yaw

  • Roll: x축을 중심으로 회전
  • Pitch: y축을 중심으로 회전
  • Yaw: z축을 중심으로 회전

이번 예제는 xy 평면만 움직이므로 roll과 pitch는 0이고 yaw만 계산한다.

from tf_transformations import quaternion_from_euler

quaternion = quaternion_from_euler(
    0.0,  # roll
    0.0,  # pitch
    yaw,
)
Quaternion 순서: quaternion_from_euler() 반환값과 ROS 메시지는 모두 여기서 (x, y, z, w) 순서로 사용한다.

6. my_tf_2: 원 중심을 바라보는 자세 발행

현재 위치가 (x, y)라면 원점 방향 벡터는 (-x, -y)다. 이 벡터의 방향각을 atan2로 계산하면 moving_frame의 x축이 world 원점을 바라보게 할 수 있다.

yaw = atan2(-y, -x)
x = 2.0 * math.cos(self.angle)
y = 2.0 * math.sin(self.angle)

# 현재 위치에서 원점으로 향하는 방향
yaw = math.atan2(-y, -x)
quaternion = quaternion_from_euler(0.0, 0.0, yaw)

transform.transform.translation.x = x
transform.transform.translation.y = y

transform.transform.rotation.x = quaternion[0]
transform.transform.rotation.y = quaternion[1]
transform.transform.rotation.z = quaternion[2]
transform.transform.rotation.w = quaternion[3]

self.broadcaster.sendTransform(transform)

my_tf_1과 my_tf_2 비교

항목my_tf_1my_tf_2
이동 경로반지름 2m 원반지름 2m 원
위치시간에 따라 변화시간에 따라 변화
자세항상 단위 Quaternion원점을 향하도록 yaw 변화
RViz 관찰축 방향은 고정된 채 이동x축이 중심을 바라보며 이동
실제 검증 결과 예: 위치 [0.340, 1.971, 0], Quaternion [0, 0, -0.765, 0.644]가 함께 발행되어 회전이 변하는 것을 확인했다.

export ROS_DOMAIN_ID=18
ros2 run tf2_ros tf2_echo world moving_frame

RViz2에서 확인

  1. 다른 터미널에서 rviz2를 실행한다.
  2. Global Options의 Fixed Frame을 world로 바꾼다.
  3. Add → TF를 선택한다.
  4. TF 옵션에서 Show Names를 켜고 Marker Scale을 조절한다.
  5. my_tf_1과 my_tf_2의 축 방향 차이를 비교한다.
동시 실행 금지: 두 노드가 모두 world → moving_frame을 발행한다. 동시에 실행하면 같은 자식 프레임에 서로 다른 변환이 들어가 TF가 흔들리거나 예측할 수 없게 된다.

9. 자주 겪는 문제와 해결

RViz에 TF가 보이지 않는다
  • Fixed Frame이 정확히 world인지 확인한다.
  • 실행 터미널과 RViz의 ROS_DOMAIN_ID가 같은지 확인한다.
  • ros2 topic echo /tf로 실제 TF 발행 여부를 확인한다.
Invalid frame ID "world"가 잠깐 출력된다

Listener가 시작된 직후 첫 TF를 받기 전에는 정상적으로 잠깐 나타날 수 있다. 이후 Translation과 Rotation이 계속 출력되면 정상이다.

Quaternion 관련 경고가 나온다

회전이 없더라도 rotation.w = 1.0을 지정한다. (0,0,0,0)은 유효한 Quaternion이 아니다.

No module named tf_transformations
sudo apt install ros-jazzy-tf-transformations
가상환경에서 No module named transforms3d

ROS apt 패키지의 Python 의존성을 가상환경이 보지 못하는 경우다.

~/venv/ros/bin/python3 -m pip install transforms3d
ros2 run이 실행 파일을 찾지 못한다
  • setup.py의 entry point를 확인한다.
  • colcon build --packages-select my_tf로 다시 빌드한다.
  • source install/setup.bash를 다시 실행한다.
종료할 때 traceback이 출력된다

Jazzy의 외부 종료 신호도 정상 종료로 처리하도록 ExternalShutdownException을 함께 catch한다.

10. 복습 체크리스트와 문제

  • 부모 프레임과 자식 프레임의 차이를 설명할 수 있다.
  • TransformStamped의 시간·frame id·translation·rotation 필드를 설명할 수 있다.
  • 왜 x=2cos(θ), y=2sin(θ)가 반지름 2m 원이 되는지 설명할 수 있다.
  • Euler의 Gimbal Lock과 Quaternion의 장점을 설명할 수 있다.
  • atan2(-y, -x)가 원점 방향을 만드는 이유를 설명할 수 있다.
  • entry point가 ros2 run 명령과 어떻게 연결되는지 안다.
Q1. header.frame_id와 child_frame_id를 반대로 쓰면?

변환의 의미가 뒤집힌다. 현재 위치 값을 그대로 두고 이름만 바꾸면 실제 의도와 다른 TF가 만들어진다.

Q2. my_tf_1의 축 방향은 왜 회전하지 않을까?

모든 시점에 단위 Quaternion (0,0,0,1)을 보내므로 world와 같은 방향을 유지한다.

Q3. my_tf_2가 중심을 바라보는지 수학적으로 어떻게 확인할까?

moving_frame의 yaw 방향 단위벡터와 현재 위치에서 원점으로 향하는 벡터 (-x,-y)가 같은 방향인지 확인한다.

Q4. tf2_echo가 출력하는 transform은 무엇을 뜻할까?

tf2_echo world moving_frame은 moving_frame 데이터를 world 기준으로 표현하기 위한 변환을 보여준다.

추천 실습: 반지름을 1m와 3m로 바꿔 보고, 타이머 주기와 각도 증가량을 바꾸면서 “발행 주기”와 “실제 회전 속도”가 어떻게 달라지는지 RViz에서 비교한다.
