05.05 · LLM · GAZEBO & NAV2 AGENT

Gazebo에서 LLM으로 주행해보기

자연어 장소 명령을 검증된 LLM tool로 해석하고, ROS 2 Service와 Nav2 goal을 거쳐 Gazebo 로봇의 안전한 주행으로 연결합니다.

한 줄 정리agent_client가 질문을 Service로 보내면 agent_service가 장소·현재 위치 tool을 선택하고, 허용된 좌표만 Nav2 goal로 전달합니다.
MAP

자연어 명령의 이동 경로

Terminal 사용자
  └─ agent_client  → /llm_agent (Agent.srv)
                         ↓
                    agent_service
              prompt.yaml + points.yaml
                         ↓
          LangChain Agent → robot_tools.py
                         ↓
             Nav2 goal / feedback / result
                         ↓
                  Gazebo mobile robot

LLM은 직접 /cmd_vel을 만들지 않습니다. 의미 해석과 tool 선택까지만 맡고, 실제 경로 계획·장애물 회피·취소는 Nav2가 담당하도록 경계를 둡니다.

01

World와 package 설치

cd ~/pinky_pro/src
git clone -b ros2-jazzy \
  https://github.com/Juancams/aws-robomaker-small-house-world.git
git clone https://github.com/PinkWink/mobile_robot_llm.git

cd ~/pinky_pro
rosdep update
rosdep install --from-paths . --ignore-src -r -y
colcon build
source install/setup.bash
pip install \
  "langchain==0.1.20" \
  "langchain-core==0.1.52" \
  "langchain-community==0.0.38" \
  "langchain-openai==0.1.7" --break-system-packages

강의 재현에는 지정 버전을 사용합니다. 다른 프로젝트와 충돌하지 않도록 가능하면 Python 가상환경을 별도로 만드세요.

02

Gazebo·Nav2·RViz

ros2 launch pinky_llm launch_sim.launch.xml
ros2 launch pinky_llm bringup_launch.xml use_sim_time:=true
ros2 launch pinky_navigation nav2_view.launch.xml

시뮬레이션에 참여하는 node는 같은 simulation clock을 사용해야 합니다. 각 launch file이 지원하는 인자를 ros2 launch ... --show-args로 확인하고 use_sim_time:=true를 일관되게 적용합니다.

Costmap 안전 여유: local/global costmap의 inflation_radius를 키우면 장애물과 간격이 넓어집니다. cost_scaling_factor를 낮추면 비용이 더 멀리 유지되어 넓은 경로를 선호합니다. 값 변경 후 좁은 통로 통과 가능 여부도 다시 시험하세요.
03

장소 정보와 Prompt

pinky_llm/
├── params/
│   ├── prompt.yaml   # Agent 역할·규칙·tool 지침
│   └── points.yaml   # 장소 이름과 map 좌표
└── pinky_llm/
    └── .env          # OPENAI_API_KEY, Git 제외

“회의실로 가”를 처리하려면 장소 이름을 points.yaml의 좌표로 찾고 Nav2 goal로 변환합니다. Prompt에는 사용할 수 있는 tool, 확인 질문, 실패 처리 규칙을 명시합니다.

OPENAI_API_KEY=your_key_here

.env는 반드시 .gitignore에 추가하고, Key를 코드·PDF·화면 캡처에 넣지 않습니다.

Interface를 추가하거나 수정한 뒤에는 workspace를 다시 build하고, 새 terminal마다 overlay를 source해야 Service type을 찾을 수 있습니다.

05

세 Python node의 역할

  • agent_client.py: terminal 질문을 받아 /llm_agent Service request의 question으로 전달
  • agent_service.py: 환경변수·Prompt·장소를 읽고 Agent를 실행해 answer 반환
  • robot_tools.py: 장소 목록, 현재 위치, Nav2 이동 등 로봇 기능을 제한된 tool로 제공

Service callback은 예외를 잡아 오류 메시지나 안전한 fallback을 반환해야 합니다. 긴 주행은 Service 자체에 묶기보다 Nav2 Action의 feedback·result·cancel을 함께 관찰합니다.

06

질문으로 tool 선택 확인

질문기대 동작
너가 갈 수 있는 곳은 어디어디야?list_locations로 등록 장소 반환
지금 어디니?get_current_location으로 현재 pose와 가까운 장소 판단
회의실로 가등록 좌표 확인 후 Nav2 goal 전송

답변 문장만 보지 말고 service log, 선택된 tool, goal 좌표, Nav2 result까지 함께 확인해야 성공 여부를 판단할 수 있습니다.

07

LLM과 실제 이동 사이의 안전 경계

  • 이동 대상은 points.yaml allowlist 안에서만 선택합니다.
  • 좌표 범위·frame ID·Quaternion을 controller 앞에서 검증합니다.
  • LLM이 직접 속도를 생성하거나 /cmd_vel을 publish하지 않게 합니다.
  • Nav2 feedback, timeout, cancel, result를 기록합니다.
  • LiDAR가 보지 못하는 낮거나 투명한 장애물을 별도로 확인합니다.
  • 시뮬레이션에서도 충돌할 수 있으므로 초기 시험은 낮은 속도와 넓은 공간에서 합니다.
08

문제 해결

  • Package를 못 찾음: build 성공 여부와 source ~/pinky_pro/install/setup.bash 확인
  • Service type 없음: Agent.srv와 CMake interface 목록 확인 후 rebuild
  • Robot이 움직이지 않음: Nav2 lifecycle, map/TF, initial pose, goal frame 확인
  • 시간·TF 오류: 관련 node의 use_sim_time 값 통일
  • 장소를 모름: points.yaml 이름·들여쓰기와 Prompt의 tool 설명 확인
  • 벽에 가까이 감: footprint·inflation과 실제 sensor blind spot 확인
  • API 인증 실패: `.env` 위치·변수 이름·계정 사용 권한 확인

실습별 실행 순서

각 실습의 완료 확인을 통과한 뒤 다음 실습으로 넘어갑니다. Terminal 번호가 다르면 새 terminal을 열고 환경을 다시 source합니다.

실습 1 · 패키지 설치와 빌드

목표: Small House World와 LLM package를 설치하고 ROS 2 interface까지 build합니다.

cd ~/pinky_pro/src
git clone -b ros2-jazzy \
  https://github.com/Juancams/aws-robomaker-small-house-world.git
git clone https://github.com/PinkWink/mobile_robot_llm.git

cd ~/pinky_pro
rosdep update
rosdep install --from-paths . --ignore-src -r -y

pip install \
  "langchain==0.1.20" \
  "langchain-core==0.1.52" \

colcon build

완료 확인: ros2 pkg list | grep pinky_llm에서 package가 보이고 ros2 interface show pinky_interfaces/srv/Agent에 question / answer가 표시됩니다.

실습 2 · Gazebo와 Nav2 실행

목표: Gazebo에 로봇을 소환하고 Nav2와 RViz를 simulation clock으로 연결합니다.

# Terminal 1 · Gazebo
source ~/pinky_pro/install/setup.bash
ros2 launch pinky_llm launch_sim.launch.xml

# Terminal 2 · Nav2 bringup
source ~/pinky_pro/install/setup.bash
ros2 launch pinky_llm bringup_launch.xml use_sim_time:=true

# Terminal 3 · RViz
source ~/pinky_pro/install/setup.bash
ros2 launch pinky_navigation nav2_view.launch.xml
강의자료 표기 차이: 마지막 실행 요약은 use_sim_time:=true를 launch_sim에 붙이지만, 앞쪽 실습과 bringup_launch.xml 내부에는 Nav2용 use_sim_time 인자가 있고 기본값이 False로 나옵니다. 따라서 여기서는 Nav2 bringup에 명시합니다.

완료 확인: Gazebo에 로봇이 보이고, RViz의 map·LaserScan·robot pose가 겹치며 Navigation lifecycle이 active입니다.

실습 3 · 장소·Prompt·LLM Agent 실행

목표: 장소 좌표와 API 환경을 준비하고 Agent Service를 실행합니다.

# 실행 전 확인
# pinky_llm/params/points.yaml
# pinky_llm/params/prompt.yaml
# pinky_llm/pinky_llm/.env

# Terminal 4 · Agent Service
source ~/pinky_pro/install/setup.bash

완료 확인: Service가 오류 없이 시작되고 ros2 service list | grep llm_agent에서 /llm_agent가 확인됩니다.

실습 4 · Agent Client와 질문 테스트

목표: 질문에 따라 올바른 tool이 선택되고, 장소 명령이 Nav2 goal로 변환되는지 검증합니다.

# Terminal 5 · Agent Client
source ~/pinky_pro/install/setup.bash
ros2 run pinky_llm agent_client

# 질문 1: 너가 갈 수 있는 곳은 어디어디야?
# 기대: list_locations

# 질문 2: 지금 어디니?
# 기대: get_current_location

# 질문 3: 회의실로 가
# 기대: points.yaml 좌표 → Nav2 goal

완료 확인: Agent 답변뿐 아니라 Terminal 4의 tool log, RViz의 goal·path, Nav2 feedback/result까지 확인합니다.

전체 완료 체크리스트

  1. Gazebo world, robot, map, LaserScan이 정상입니다.
  2. 모든 simulation node의 clock 설정이 일치합니다.
  3. points.yaml의 장소 좌표를 RViz에서 확인했습니다.
  4. 장소 목록·현재 위치 질문이 올바른 tool을 선택합니다.
  5. 이동 명령의 goal과 Nav2 result를 확인했습니다.
  6. API Key를 Git에서 제외했습니다.
  7. 충돌 시 즉시 cancel·정지할 수 있습니다.
