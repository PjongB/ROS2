combined_frame은 좌표계 관계를 만드는 Broadcaster다. 이번에 추가한 노드들은 그 정보를 받는 Listener다. Listener가 TF를 직접 계산하는 것이 아니라, Buffer에 수집된 변환을 조회한 다음 필요한 거리나 경로로 가공한다.

INPUT

TF Tree

world → moving_frame → child_frame 관계가 10 Hz로 들어온다.

PROCESS

조회와 계산

최신 변환의 translation을 읽어 거리 또는 이동 기록을 만든다.

OUTPUT

Topic과 RViz2

숫자 토픽, Marker, Path, 텍스트 Marker로 결과를 확인한다.

중요: 시각화 노드만 실행하면 좌표가 생기지 않는다. 먼저 combined_frame이 실행되어 world와 child_frame TF가 존재해야 한다.

2. Buffer, Listener, lookup_transform

구성요소역할핵심 문법
Buffer시간에 따라 들어온 TF 변환을 캐시한다.Buffer()
TransformListener/tf, /tf_static을 구독해 Buffer를 채운다.TransformListener(buffer, node)
lookup_transform두 프레임 사이의 변환을 Buffer에서 찾는다.lookup_transform(target, source, time)
TransformException프레임이 아직 없거나 시간 조건이 맞지 않을 때의 예외다.except TransformException
 
from tf2_ros import Buffer, TransformException, TransformListener

self.tf_buffer = Buffer()
self.tf_listener = TransformListener(self.tf_buffer, self)

try:
    transform = self.tf_buffer.lookup_transform(
        'world',          # target: 결과를 표현할 기준 프레임
        'child_frame',    # source: 위치를 알고 싶은 프레임
        rclpy.time.Time() # 가장 최신 변환
    )
except TransformException as error:
    self.get_logger().warning(str(error))
    return
읽는 방법: lookup_transform('world', 'child_frame', ...)은 “child_frame의 데이터를 world 좌표계로 표현하는 변환”을 요청한다. 결과의 translation은 world 원점에서 본 child_frame 위치다.

3. 두 프레임 사이의 거리 계산

TransformStamped 안쪽의 translation에서 x, y, z를 꺼내 3차원 유클리드 거리를 계산한다.

distance = √(x² + y² + z²)
translation = transform.transform.translation
distance = math.sqrt(
    translation.x ** 2
    + translation.y ** 2
    + translation.z ** 2
)

message = Float32()
message.data = float(distance)
self.distance_publisher.publish(message)

transform.transform이 반복되는 이유는 바깥 객체가 TransformStamped이고, 그 안의 transform 필드가 실제 이동·회전 정보를 가진 Transform이기 때문이다.

입력계산출력

4. Marker.LINE_STRIP으로 이동 궤적 그리기

매 순간의 위치를 Python 리스트에 넣고, 각 좌표를 Point로 바꿔 Marker의 points에 추가한다. RViz2는 배열 순서대로 점을 연결한다.

self.positions.append((x, y, z))

marker = Marker()
marker.header.frame_id = 'world'
marker.type = Marker.LINE_STRIP
marker.action = Marker.ADD
marker.pose.orientation.w = 1.0

for x, y, z in self.positions:
    point = Point()
    point.x = x
    point.y = y
    point.z = z
    marker.points.append(point)

marker.scale.x = 0.02  # LINE_STRIP의 선 굵기
marker.color.r = 1.0
marker.color.a = 1.0   # 0이면 완전히 투명
self.marker_publisher.publish(marker)

무한 궤적과 최근 궤적

노드저장 방식화면 결과
frame_trail_publisher_marker모든 위치를 계속 저장지나간 전체 경로
frame_trail_publisher_marker_2최근 20개만 저장프레임 뒤를 따르는 짧은 꼬리
 
self.positions.append((x, y, z))
if len(self.positions) > self.max_points:
    self.positions.pop(0)  # 가장 오래된 첫 번째 점 제거
메모리: 전체 경로 예제는 학습용이다. 장시간 동작하는 실제 시스템에서는 길이 제한, 다운샘플링, 기록 파일 분리를 고려해야 한다.

5. PoseStamped와 nav_msgs/Path

Path는 PoseStamped[] 배열이다. Point만 저장하는 Marker와 달리 위치뿐 아니라 Quaternion 방향도 함께 저장할 수 있어 네비게이션 경로 표현에 적합하다.

self.path_message = Path()
self.path_message.header.frame_id = 'world'

pose = PoseStamped()
pose.header.stamp = now
pose.header.frame_id = 'world'
pose.pose.position.x = transform.transform.translation.x
pose.pose.position.y = transform.transform.translation.y
pose.pose.position.z = transform.transform.translation.z
pose.pose.orientation = transform.transform.rotation

self.path_message.poses.append(pose)
self.path_message.header.stamp = now
self.path_publisher.publish(self.path_message)
비교Marker.LINE_STRIPnav_msgs/Path
배열 요소PointPoseStamped
방향 정보없음Quaternion 포함
스타일 설정메시지에서 색·두께 지정RViz Path 디스플레이에서 지정
대표 용도커스텀 선·도형계획 경로·주행 궤적
슬라이딩 윈도우: frame_trail_publisher_nav_2는 path_message.poses.pop(0)으로 최근 50개 Pose만 유지한다.

6. Path + 거리 + 3D 텍스트 통합

frame_trail_publisher_nav_3는 한 번의 TF 조회 결과를 세 가지 출력으로 재사용한다.

PATH

/frame_path

최근 50개의 PoseStamped를 경로로 발행한다.

NUMBER

/child_frame_distance

다른 노드가 사용할 수 있는 Float64 거리 값이다.

TEXT

/distance_marker

RViz 카메라를 바라보는 거리 문자열이다.

marker.type = Marker.TEXT_VIEW_FACING
marker.pose.position.x = translation.x
marker.pose.position.y = translation.y
marker.pose.position.z = translation.z + 0.5
marker.pose.orientation.w = 1.0
marker.scale.z = 0.5
marker.color.a = 1.0
marker.text = f'Distance: {distance:.2f} m'

TEXT_VIEW_FACING은 보는 방향이 바뀌어도 글자가 카메라를 향한다. 텍스트 크기는 LINE_STRIP의 scale.x와 달리 scale.z로 설정한다.

7. 타이머 콜백 알고리즘

  1. 노드 시작 시 Buffer, TransformListener, Publisher, 0.1초 타이머를 생성한다.
  2. Listener가 /tf와 /tf_static을 구독해 Buffer에 변환을 축적한다.
  3. 타이머가 0.1초마다 콜백을 호출한다.
  4. lookup_transform('world', 'child_frame', Time())으로 최신 변환을 요청한다.
  5. 변환이 아직 없으면 TransformException을 처리하고 이번 콜백만 끝낸다.
  6. 성공하면 translation과 rotation을 꺼낸다.
  7. 노드 목적에 따라 거리 계산, Point 누적 또는 PoseStamped 누적을 수행한다.
  8. 최대 길이가 정해진 예제는 오래된 첫 요소를 제거한다.
  9. Float, Marker 또는 Path 메시지를 완성해 토픽으로 발행한다.
  10. RViz2나 ros2 topic echo가 출력 토픽을 구독해 결과를 보여준다.
핵심 설계: 한 번 가져온 TF를 여러 결과로 바꿀 수 있다. nav_3가 같은 translation으로 Path, 숫자 거리, 텍스트 Marker를 만드는 것이 좋은 예다.

11. 자주 겪는 문제

실행했는데 창이 나오지 않는다

ROS 노드는 보통 GUI가 아니다. 터미널에서 계속 실행되는 것이 정상이다. 별도 터미널에서 rviz2를 실행하고 Fixed Frame과 디스플레이 토픽을 설정한다.

Invalid frame ID 또는 Could not transform 경고

combined_frame을 먼저 실행했는지 확인한다. 시작 직후 첫 TF가 Buffer에 들어오기 전 한두 번의 경고는 정상일 수 있다.

ros2 run이 실행 파일을 찾지 못한다

colcon build --packages-select my_tf --symlink-install 후 현재 터미널에서 source ~/dev_ws/ros/install/local_setup.bash를 다시 실행한다.

RViz에 Path나 Marker가 보이지 않는다
  • Fixed Frame이 world인지 확인한다.
  • Path Topic이 /frame_path인지 확인한다.
  • Marker Topic이 목적에 따라 /frame_trail_marker 또는 /distance_marker인지 확인한다.
  • 각 터미널의 ROS_DOMAIN_ID가 같은지 확인한다.
텍스트는 있는데 선이 안 보인다

nav_3의 선은 Marker가 아니라 Path다. RViz에 Marker뿐 아니라 Path 디스플레이도 추가해야 한다.

경로가 이상하게 겹치거나 떨린다

같은 출력 토픽을 쓰는 Marker 변형 또는 Path 변형을 동시에 실행했는지 확인한다. 비교 대상 외 노드는 Ctrl+C로 종료한다.

12. ROS 2 TF 문법 퀴즈 20문항

각 문제에서 하나를 선택한 뒤 아래의 채점하기를 누른다. 채점 후 정답과 해설이 표시된다.

1. ROS 2 Python 노드의 부모 클래스를 가져오는 올바른 문법은?

정답 B. Node는 rclpy.node 모듈에서 가져온다.

2. TF 데이터를 시간별로 저장하는 객체 생성 문법은?

정답 A. Buffer가 수신된 변환을 캐시한다.

3. Listener를 현재 노드에 연결하는 올바른 문법은?

정답 C. 첫 인자는 채울 Buffer, 두 번째 인자는 구독을 생성할 Node다.

4. TF에서 가장 최신 변환을 요청할 때 사용하는 시간 표현은?

정답 B. 기본 생성된 Time은 TF2에서 최신 변환 조회에 사용한다.

5. world 기준 child_frame 변환을 조회하는 인자 순서는?

정답 A. 순서는 target, source, time이다.

6. 조회 결과에서 x 이동량을 읽는 문법은?

정답 C. 반환 타입은 TransformStamped이고 내부 transform의 translation을 읽는다.

7. 3차원 유클리드 거리 계산 문법으로 맞는 것은?

정답 B. 각 축 차이의 제곱합에 제곱근을 취한다.

8. Float32 거리 Publisher를 만드는 문법은?

정답 A. create_publisher의 인자는 메시지 타입, 토픽, QoS depth다.

9. std_msgs/Float32 객체에 실제 값을 저장하는 필드는?

정답 C. 표준 단일 값 메시지는 data 필드를 사용한다.

10. 약 10 Hz로 콜백을 실행하는 타이머 문법은?

정답 B. 주기 0.1초의 역수는 초당 10회다.

11. 점들을 순서대로 연결하는 Marker 타입은?

정답 A. LINE_STRIP은 points 배열 순서대로 선분을 잇는다.

12. LINE_STRIP에 새 Point를 추가하는 문법은?

정답 C. points는 Point 메시지의 리스트다.

13. LINE_STRIP의 선 굵기를 설정하는 필드는?

정답 B. LINE_STRIP에서는 scale.x가 선 너비다.

14. Marker를 완전히 불투명하게 만드는 문법은?

정답 A. alpha 범위는 0.0~1.0이며 1.0이 불투명이다.

15. PoseStamped 목록으로 이루어진 경로 메시지 타입은?

정답 C. Path의 poses 필드는 PoseStamped 배열이다.

16. Path에 새 PoseStamped를 추가하는 문법은?

정답 B. poses는 Python 리스트처럼 append를 사용한다.

17. 리스트에서 가장 오래된 첫 요소를 제거하는 문법은?

정답 A. 인덱스 0은 리스트 맨 앞, 즉 가장 먼저 저장된 요소다.

18. 항상 RViz 카메라를 향하는 텍스트 Marker 타입은?

정답 C. TEXT_VIEW_FACING이 시점 방향에 맞춰 글자를 회전한다.

19. TEXT_VIEW_FACING 글자 높이를 설정하는 필드는?

정답 B. 텍스트 Marker의 높이는 scale.z로 정한다.

20. setup.py에 ROS 실행 명령을 등록하는 형식은?
