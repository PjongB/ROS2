01

6개 감정과 대응 전략

강의는 6개 감정을 정의하고, 감정마다 색상·표정·움직임을 연결합니다. 문자열 표기를 한 곳에서 상수로 관리하고 알 수 없는 값은 neutral 같은 안전 상태로 처리합니다.

ALLOWED_EMOTIONS = {
    "happy", "sad", "angry",
    "interest", "surprise", "neutral",
}
02

LED·LCD·Motor 초기화

  • 장치 객체를 한 번 생성하고 정상 연결 여부를 확인합니다.
  • 실행 전 LED clear와 motor stop으로 초기 상태를 통일합니다.
  • 예외·KeyboardInterrupt·종료 시 반드시 motor stop, LED clear, LCD·camera close를 실행합니다.
03

LED 색상으로 감정 표현

감정→RGB 또는 색상 순환 패턴 dictionary를 만들고, 하나의 show_emotion_led() 함수가 장치 호출을 담당하게 합니다.

EMOTION_COLORS = {
    "happy": [(255, 180, 0), (255, 255, 0)],
    "sad": [(0, 40, 255)],
    "angry": [(255, 0, 0)],
    "neutral": [(40, 40, 40)],
}

class가 지원하는 method는 dir(object)로 확인할 수 있으며, 실습 끝에는 clear합니다.

04

LCD에 감정 GIF 표시

  • emotion resource folder에서 지원 GIF 목록을 확인합니다.
  • GIF frame을 순회해 LCD에 표시합니다.
  • 재생 시간이 길면 frame 간격·반복 수·전체 duration을 제한합니다.
  • 없는 표정 파일은 neutral image로 대체합니다.
05

Motor movement로 감정 표현

  • 좌우 흔들기
  • 앞뒤 흔들기
  • 앞으로 한 번 움찔
  • angry·interest 등 감정별 sequence

속도와 duration에 상한을 두고, sequence 사이마다 정지 명령을 보냅니다. 장애물·낙하 센서 조건이 만족되지 않으면 움직이지 않습니다.

06

Camera frame 한 장 획득

def capture_one_frame(cam):
    frame = cam.get_frame()
    image = Image.fromarray(frame)
    image.save("capture.jpg", format="JPEG")
    return image

실제 camera API 이름과 color format은 설치된 Pinky library를 확인합니다. frame이 없으면 API 호출을 중단합니다.

07

대화와 감정 추론

system prompt에 “감정을 반드시 6개 중 하나로 추론”하도록 요구하고, 사용자 text와 history를 함께 전달합니다. 응답은 최소한 emotion과 reply로 분리합니다.

{
  "emotion": "happy",
  "reply": "오늘 만나서 정말 반가워!"
}

emotion을 허용 목록과 대조한 뒤 LED·LCD·motor 함수를 호출합니다.

08

사진을 보고 감정 표현

  1. camera frame을 JPEG로 변환합니다.
  2. binary를 Base64 data URL로 변환합니다.
  3. Vision model에 image와 감정 분류 prompt를 보냅니다.
  4. JSON을 parsing하고 emotion 허용값을 검사합니다.
  5. 검증된 감정에 맞춰 행동합니다.

사진 속 사람의 감정 추론은 부정확할 수 있으므로 확정적 판단이나 민감한 의사결정에 사용하지 않습니다.

09

Robot safety boundary

  • LLM은 직접 motor command를 만들지 않고 허용된 emotion code만 선택합니다.
  • controller가 속도·duration·sensor stop 조건을 강제합니다.
  • API timeout·JSON 실패·unknown emotion이면 motor를 정지합니다.
  • 대화 history에 API Key와 개인 image metadata를 넣지 않습니다.
  • 종료 handler에서 모든 actuator를 안전 상태로 되돌립니다.

전체 실행 순서

1. API Key와 dependency 준비
2. LED·LCD·motor·camera 개별 test
3. 6개 emotion mapping 정의
4. text → {emotion, reply} API test
5. emotion validation
6. LED → LCD → motor 순차 동작
7. camera → Base64 → vision 감정 추론
8. 오류 시 stop·clear·close

체크리스트

  1. 각 hardware를 독립적으로 검증했습니다.
  2. 6개 감정과 fallback을 정의했습니다.
  3. LLM JSON 결과를 검증합니다.
  4. motor safety limit와 sensor stop을 적용했습니다.
  5. API 오류 시 안전 종료됩니다.
