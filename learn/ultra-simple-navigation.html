Ultra Simple Navigation

Nav2의 복잡한 기능에 들어가기 전에, TF로 현재 자세를 읽고 PID와 상태 머신으로 목표 위치·방향까지 주행하는 원리를 직접 구현합니다.

KEY

반드시 기억할 핵심 포인트

34장 강의와 예제 코드 요약

  • 입력: RViz2의 2D Goal Pose가 geometry_msgs/PoseStamped 형식으로 /goal_pose에 들어옵니다.
  • 현재 자세: 토픽을 별도로 구독하지 않고 TF Buffer에서 map → base_footprint 변환을 조회합니다.
  • 출력: 계산한 선속도와 각속도를 geometry_msgs/Twist로 /cmd_vel에 발행합니다.
  • 제어 주기: 타이머가 0.1초마다 제어 루프를 실행합니다.
  • 허용 오차: 각도 0.05rad, 거리 0.15m 이내이면 다음 상태로 넘어갑니다.
  • 상태 순서: idle → rotate_to_goal → move_to_goal → rotate_to_final → idle입니다.
  • 주의: 예제는 장애물 감지·경로 계획·복구 기능이 없는 직선 기반 교육용 내비게이터입니다.

Twist.linear.x는 전진 속도이고 Twist.angular.z는 회전 속도입니다. 내비게이터는 이 두 값만으로 2D 이동을 제어합니다.

01

pinky_simple_navigator 패키지 준비

원본 5–7쪽

  • 강의의 예제 저장소는 PinkWink/pinky_for_edu이며 필요한 폴더는 pinky_simple_navigator입니다.
  • package.xml은 rclpy, geometry_msgs, tf2_ros, tf_transformations에 의존합니다.
  • setup.py의 콘솔 스크립트 simple_navigator가 Python의 main()을 실행합니다.
  • 패키지를 복사한 뒤 워크스페이스에서 빌드하고 새 설치 환경을 source합니다.
02

PID와 각도 정규화

원본 8–11쪽

  • PID.update()는 현재 오차에 P·I·D 항을 적용해 속도 명령을 계산합니다.
  • 각속도 제어기는 P=1.5, D=0.2, 선속도 제어기는 P=0.5, D=0.1을 사용합니다.
  • 현재 설정은 I=0이므로 누적 오차를 사용하지 않는 PD 제어에 가깝습니다.
  • 새 목표를 받으면 두 PID의 누적 오차와 이전 오차를 초기화합니다.
출력 = P × 현재 오차
     + I × 누적 오차
     + D × 오차 변화량

atan2(sin(angle), cos(angle))로 각도 오차를 −π에서 π 사이로 정규화합니다. 예를 들어 현재 방향이 179°이고 목표가 −179°라면 358°를 도는 대신 가장 짧은 2°만 회전하게 됩니다.

03

TF를 읽고 goal_pose를 받아 cmd_vel 발행

원본 12–18쪽

  • TransformListener가 채운 Buffer에서 로봇의 x·y와 quaternion을 읽고 yaw로 변환합니다.
  • /goal_pose 콜백은 목표를 저장하고 상태를 rotate_to_goal로 전환합니다.
  • 목표가 없거나 idle이면 빈 Twist를 발행해 로봇을 정지시킵니다.
  • TF 조회 실패 시 경고를 남기고 해당 제어 주기를 건너뜁니다. 강의 원본은 base_link를 사용하지만 현재 Pinky Pro 코드는 실제 TF에 맞춰 base_footprint를 사용합니다.
04

세 단계 상태 머신

원본 19–21쪽

idle
  ↓ 목표 수신
rotate_to_goal
  ↓ 목표 지점을 바라봄
move_to_goal
  ↓ 목표 위치 도착
rotate_to_final
  ↓ 최종 방향 일치
idle
  • rotate_to_goal: atan2(goal_y-current_y, goal_x-current_x)로 목표 방위각을 구해 먼저 제자리 회전합니다.
  • move_to_goal: sqrt(dx²+dy²)로 남은 거리를 구해 전진하고, 이동 중에도 각도 오차를 계속 보정합니다.
  • rotate_to_final: 목표 위치 도착 후 PoseStamped의 quaternion을 yaw로 변환해 최종 방향을 맞춥니다.
  • 최종 방향 오차가 허용 범위에 들어오면 목표를 비우고 idle로 복귀합니다.
05

허용 오차가 필요한 이유

목표 주변 진동 방지

  • angle_tolerance = 0.05rad는 약 2.9° 이내를 방향 일치로 판단합니다.
  • distance_tolerance = 0.15m는 목표에서 15cm 이내를 위치 도착으로 판단합니다.
  • 완전히 같은 좌표를 요구하면 센서 노이즈와 관성 때문에 로봇이 목표 주변에서 계속 진동할 수 있습니다.
  • 허용 오차를 너무 크게 하면 부정확하게 멈추고, 너무 작게 하면 목표 달성이 어려워집니다.
06

Gazebo·Localization·RViz2와 함께 실행

원본 22–31쪽

  • simple_drive.launch.xml은 use_sim_time: true로 내비게이터 노드 하나를 실행합니다.
  • Gazebo와 Localization을 시작하고 RViz2에서 2D Pose Estimate로 초기 위치와 방향을 맞춥니다.
  • 그다음 2D Goal Pose로 지도 위의 목표 위치를 클릭하고 원하는 최종 방향으로 드래그합니다.
  • TF 표시가 복잡하면 필요한 프레임만 남겨 이동 결과를 관찰합니다.
07

간단한 구현의 한계

원본 32–33쪽

  • 목표까지 직선으로 움직이므로 앞의 장애물을 감지하거나 회피하지 못합니다.
  • 전역·지역 costmap과 경로 계획기가 없어 벽을 피해가는 비선형 경로를 만들 수 없습니다.
  • 위치 추정을 잃거나 로봇이 막혔을 때 후진·재계획하는 복구 시나리오가 없습니다.
  • 이 기능들을 계층적으로 제공하는 Nav2를 배우기 전에 기본 데이터 흐름과 제어 원리를 확인하는 데 목적이 있습니다.

핵심 실행 명령

source /opt/ros/jazzy/setup.bash

# 패키지를 ~/pinky/src에 복사한 뒤 빌드
cd ~/pinky
colcon build --symlink-install
source install/setup.bash

# 터미널 1: Gazebo
ros2 launch pinky_gz_sim launch_sim.launch.xml

# 터미널 2: 저장된 지도로 위치 추정
ros2 launch pinky_navigation localization_only_launch.xml map:=my_map.yaml

# 터미널 3: RViz2
ros2 launch pinky_navigation nav2_view.launch.xml

# 터미널 4: 단순 PID 내비게이터
ros2 launch pinky_simple_navigator simple_drive.launch.xml

# 연결 확인
ros2 topic echo /goal_pose
ros2 topic echo /cmd_vel
ros2 run tf2_ros tf2_echo map base_footprint
