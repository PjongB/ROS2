05.08 · LLM · RAG + OLLAMA + CHROMADB

LLM에 RAG 추가하기

PinkyPro 전용 문서를 검색해 관련 부분만 prompt에 넣고, 작은 로컬 LLM의 답변을 문서에 근거하도록 개선합니다.

원본 HTML강의 PDF완성 코드실행 순서 ↓
강의 목차RAG 개념실습 전 준비터미널 순서실습별 구성튜닝·검증문제 해결
한 줄 정리질문 → embedding 검색 → 관련 문서 chunk → prompt 보강 → LLM 답변 순서이며, RAG는 환각을 줄이지만 정답을 보장하지는 않습니다.
01

왜 RAG가 필요한가

사용자 질문 ↓ embedding ChromaDB에서 유사 chunk top 3 검색 ↓ context 결합 Ollama LLM에 질문 ↓ PinkyPro 문서 기반 답변

  • 기본 LLM은 학습하지 않은 Pinky library API를 알기 어렵습니다.
  • RAG는 모델을 재학습하지 않고 외부 문서를 매 질문마다 제공합니다.
  • mxbai-embed-large는 text를 vector로 바꾸고, ChromaDB는 비슷한 vector를 찾습니다.
02

실습 전 다운로드·파일 준비

현재 다운로드 폴더에는 pinky_library.md가 없습니다. 강의에서 제공하는 파일을 받아 아래 작업 폴더에 넣어야 RAG 실습이 시작됩니다.
~/llm_rag/
├── ask_llm_rag.py
├── pinky_library.md       # 필수 강의 문서
└── pinky_rag_db/          # 첫 실행 때 자동 생성

터미널에 입력하는 전체 순서

# 1. Ollama가 설치·실행 중인지 확인
ollama --version
curl http://localhost:11434/api/tags

# 2. 작업 폴더 생성
mkdir -p ~/llm_rag
cd ~/llm_rag

# 3. 생성된 완성 코드와 강의의 pinky_library.md를 이 폴더에 복사
# 브라우저에서 ask-llm-rag.py를 받은 경우 예시
cp ~/Downloads/ask-llm-rag.py ./ask_llm_rag.py

# 4. 생성 모델과 embedding 모델 다운로드
ollama pull hf.co/rippertnt/HyperCLOVAX-SEED-Text-Instruct-1.5B-Q4_K_M-GGUF:Q4_K_M
ollama pull mxbai-embed-large

# 5. Python package 설치
python3 -m pip install chromadb langchain-text-splitters requests

# 6. 파일 확인 후 실행
ls -l ask_llm_rag.py pinky_library.md
python3 ask_llm_rag.py
03

실습별 실행 순서

실습 1 · 기본 LLM의 한계 확인

RAG 없이 Pinky 전용 질문을 던져 모르는 API를 추측하는지 기록합니다.

ollama run hf.co/rippertnt/HyperCLOVAX-SEED-Text-Instruct-1.5B-Q4_K_M-GGUF:Q4_K_M

Pinky 라이브러리로 모터를 앞으로 움직이는 방법을 알려줘.
/bye

실습 2 · 문서 인덱싱과 RAG 실행

cd ~/llm_rag
python3 ask_llm_rag.py

첫 실행은 Markdown을 500자, 50자 overlap으로 나눠 embedding DB를 만듭니다. 같은 질문을 넣고 [검색 문서]와 답변이 일치하는지 확인합니다.

실습 3 · 더 큰 모델 비교

ollama pull qwen3:4b
# ask_llm_rag.py의 MODEL_NAME을 qwen3:4b로 바꾼 뒤
python3 ask_llm_rag.py

1.5B와 4B에서 근거 충실도·정확도·응답 시간을 같은 질문으로 비교합니다.

04

검색 품질을 조절하는 값

  • chunk_size=500: 너무 작으면 문맥이 끊기고, 너무 크면 무관한 내용이 섞입니다.
  • chunk_overlap=50: 경계에서 잘린 의미를 이어 줍니다.
  • top_k=3: 관련 문서 수입니다. 늘리면 정보와 prompt 길이가 함께 증가합니다.
  • 답변만 보지 말고 코드가 출력하는 검색 chunk가 실제 질문과 관련 있는지 먼저 확인합니다.
  • 문서 밖 내용은 추측하지 말라는 prompt가 있어도 결과를 검증해야 합니다.

DB 갱신·문제 해결

# Markdown을 수정했다면 기존 DB를 보관하고 새로 생성
cd ~/llm_rag
mv pinky_rag_db pinky_rag_db_backup
python3 ask_llm_rag.py

# Ollama 상태와 모델 확인
curl http://localhost:11434/api/tags
ollama list

# package import 확인
python3 -c "import chromadb, requests; from langchain_text_splitters import RecursiveCharacterTextSplitter; print('OK')"
  • MD 파일 없음: 파일명·현재 폴더·확장자를 확인합니다.
  • Connection refused: Ollama service를 먼저 실행합니다.
  • 모델 not found: 두 모델을 ollama pull했는지 확인합니다.
  • 수정 내용이 반영 안 됨: 기존 DB를 backup으로 옮긴 뒤 다시 실행합니다.
  • 답변이 틀림: 검색 chunk, 문서 원문, chunk 크기, top_k를 순서대로 점검합니다.
