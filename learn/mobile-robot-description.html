01

설치부터 시작

원본 HTML 4–16

  • 워크스페이스는 ~/pinky, 소스는 ~/pinky/src에 둡니다.
  • rosdep으로 의존성을 설치하고 colcon build로 빌드합니다.
  • 빌드 후 현재 터미널에서 source ~/pinky/install/local_setup.bash를 실행합니다.
02

Description 패키지 개요

원본 HTML 17–21

  • launch는 실행 구성, urdf는 로봇 구조, meshes는 3D 형상, rviz는 화면 설정입니다.
  • package.xml은 의존성, CMakeLists.txt는 리소스 설치 규칙을 담당합니다.
  • DAE는 주로 화면 표시, STL은 주로 충돌 형상에 사용합니다.
03

view_robot.launch.py

원본 HTML 22–29

  • Node로 RViz2, robot_state_publisher, joint_state_publisher_gui를 실행합니다.
  • Command가 Xacro를 전개하고 결과 XML을 robot_description에 넣습니다.
  • get_package_share_directory()로 설치된 패키지의 파일 경로를 찾습니다.
04

URDF와 Xacro

원본 HTML 30–45

  • URDF는 XML 형식으로 로봇의 link와 joint 구조를 표현합니다.
  • Xacro는 변수·수식·매크로·조건문을 사용해 반복되는 URDF를 줄입니다.
  • robot.urdf.xacro가 진입점이고 pinky.urdf.xacro의 insert_robot 매크로를 호출합니다.
05

Link와 Joint

원본 HTML 46–64

  • link는 부품 또는 좌표 프레임이고 joint는 부모·자식 link의 관계입니다.
  • origin xyz/rpy는 장착 위치와 방향, axis는 관절 운동축입니다.
  • Pinky의 고정부는 fixed, 구동 바퀴와 캐스터는 주로 continuous를 사용합니다.
06

Visual·Collision·Inertial

원본 HTML 40–44·49–52

  • visual은 보이는 형상, collision은 충돌 계산 형상입니다.
  • inertial에는 질량, 무게중심, 관성 텐서를 정의합니다.
  • 잘못된 관성값은 Gazebo에서 떨림이나 발산을 만들 수 있습니다.
07

센서 Frame과 TF

원본 HTML 65–75

  • LiDAR·카메라·IMU·초음파 link는 센서 데이터의 좌표 기준입니다.
  • 형상이 없는 빈 link도 header.frame_id와 TF를 위한 프레임으로 필요할 수 있습니다.
  • 물리적인 mount와 실제 측정 기준 sensor frame을 분리하면 관리하기 쉽습니다.
08

Upload·RViz·Gazebo

원본 HTML 76–90

  • view_robot은 바로 확인하는 용도이고 upload_robot은 다른 시스템에 모델을 제공하는 용도입니다.
  • RViz RobotModel에서 Description Topic을 /robot_description으로 설정합니다.
  • RViz 설정은 .rviz로 저장하고 rviz2 -d 파일명.rviz로 재사용합니다.

터미널 실행 순서

source /opt/ros/jazzy/setup.bash
source ~/pinky/install/local_setup.bash
ros2 launch pinky_description view_robot.launch.py

# 모델만 업로드
ros2 launch pinky_description upload_robot.launch.py

# 시뮬레이션
ros2 launch pinky_gz_sim launch_sim.launch.xml
