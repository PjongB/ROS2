로봇 파라미터·RQT 설정 가이드

Nav2·Costmap·AMCL·Controller·SLAM 설정의 의미를 읽고, RQT와 CLI로 한 항목씩 안전하게 변경·검증·저장하는 실전 참고서입니다.

01

변경 전에 먼저 확인할 것

  • 파라미터는 ROS 2 전체의 전역값이 아니라 각 Node가 소유하는 설정값입니다.
  • 같은 이름이라도 global_costmap과 local_costmap, PinkyPro와 TurtleBot3의 적절한 값은 다를 수 있습니다.
  • RQT에서 보인다는 사실이 “주행 중 안전하게 변경 가능”하다는 뜻은 아닙니다. read-only, lifecycle 상태, plugin 구현에 따라 변경이 거절되거나 재시작 뒤에만 적용될 수 있습니다.
  • 숫자를 바꾸기 전에 TF, 센서, footprint, 초기 위치가 정상인지 먼저 확인합니다. 구조 오류를 튜닝으로 가리면 위험합니다.
실물 로봇: 바퀴를 들거나 넓은 시험 공간을 확보하고, 속도·가속도는 작은 값부터 올립니다. footprint와 안전 반경을 통과 목적으로 거짓으로 줄이지 않습니다.
02

런타임 값과 YAML의 차이

방식언제 적용지속 여부용도
RQT / ros2 param set실행 중대부분 재시작하면 사라짐실험·비교
ros2 param load실행 중인 Node에 load재시작하면 launch 설정으로 복귀설정 묶음 시험
YAML 수정다음 launch부터파일에 남음검증된 최종값
Launch argumentNode 시작 시해당 실행 동안환경별 설정 선택

파라미터 이름을 세 부분으로 읽기

/local_costmap/local_costmap
└─ inflation_layer.inflation_radius
   ├─ plugin: inflation_layer
   └─ setting: inflation_radius

Node 이름, plugin 이름, 실제 setting 이름을 분리해서 읽으면 같은 파라미터가 여러 곳에 존재해도 혼동이 줄어듭니다.

03

RQT에서 변경하는 정확한 순서

# 새 터미널
source /opt/ros/jazzy/setup.bash

# PinkyPro 또는 TurtleBot3 workspace가 있다면 추가
source ~/pinky/install/setup.bash
# source ~/turtlebot3_ws/install/setup.bash

# 설치 확인
ros2 pkg prefix rqt_reconfigure

# 없을 때
sudo apt update
sudo apt install ros-jazzy-rqt-reconfigure -y

rqt
  1. Plugins → Configuration → Parameter Reconfigure를 엽니다.
  2. 왼쪽 Node tree에서 바꿀 Node를 선택합니다. 예: /local_costmap/local_costmap.
  3. 검색창에 inflation, velocity, tolerance처럼 일부 이름을 입력합니다.
  4. 현재값을 기록하거나 CLI로 dump합니다.
  5. 한 번에 한 항목만 작은 폭으로 변경하고 Enter를 누릅니다.
  6. RViz, ros2 param get, Topic, 실제 로봇 반응을 함께 확인합니다.
  7. 효과가 없거나 위험하면 즉시 이전 값으로 원복합니다.
플러그인 이름: 환경에 따라 메뉴가 Dynamic Reconfigure 또는 Parameter Reconfigure로 표시될 수 있습니다. Node가 목록에 없으면 Node 실행·ROS Domain·source부터 확인합니다.
04

CLI로 현재값·설명·적용 여부 확인

# Node와 parameter 탐색
ros2 node list
ros2 param list /local_costmap/local_costmap

# 설명·type·제약 확인
ros2 param describe /local_costmap/local_costmap \
  inflation_layer.inflation_radius

# 변경 전 값
ros2 param get /local_costmap/local_costmap \
  inflation_layer.inflation_radius

# 한 항목 변경
ros2 param set /local_costmap/local_costmap \
  inflation_layer.inflation_radius 0.35

# 실제 적용값 재확인
ros2 param get /local_costmap/local_costmap \
  inflation_layer.inflation_radius

백업과 복원

mkdir -p ~/robot_param_backup
ros2 param dump /local_costmap/local_costmap \
  --output-dir ~/robot_param_backup

# 생성된 YAML을 확인한 뒤 필요할 때 load
ls -l ~/robot_param_backup
ros2 param load /local_costmap/local_costmap \
  ~/robot_param_backup/local_costmap__local_costmap.yaml

실제 dump 파일명은 Node 이름과 ROS 2 버전에 따라 달라질 수 있으므로 ls로 확인합니다. 최종값은 사용 중인 Nav2 YAML의 정확한 namespace에 반영합니다.

05

Costmap 핵심 파라미터

파라미터올리면내리면주로 보는 증상
inflation_radius장애물 영향 범위가 넓어짐좁은 길 선택 가능성이 커짐벽에 붙음·통로가 막힘
cost_scaling_factor거리별 비용이 더 빨리 감소높은 비용이 멀리 유지우회가 큼·벽 가까운 경로
footprint_padding충돌 검사 외곽이 커짐통과 공간이 늘어남실제 차체 여유
update_frequency장애물 반영이 빨라지나 CPU 사용 증가부하는 줄지만 반영 지연동적 장애물 반응
publish_frequency시각화·구독 갱신 증가network·CPU 부담 감소RViz 갱신 속도
transform_tolerance일부 TF 지연을 더 허용시간 일치 요구가 엄격TF timeout
기억법: radius는 비용 영역의 끝 범위이고 cost_scaling_factor는 범위 안에서 비용이 떨어지는 속도입니다. scaling factor가 클수록 더 빨리 낮아집니다.

Global과 Local을 따로 보는 이유

  • Global: 지도 전체에서 어떤 길을 선택할지 결정합니다.
  • Local: 실제 주행 중 어떤 속도 궤적을 허용할지 결정합니다.
  • Global Path가 있어도 Local Costmap이 통로를 위험하다고 판단하면 로봇은 입구에서 멈출 수 있습니다.
ros2 param list /global_costmap/global_costmap | grep -E 'inflation|footprint|frequency'
ros2 param list /local_costmap/local_costmap | grep -E 'inflation|footprint|frequency'
06

AMCL·Localization 파라미터

파라미터의미조정 시 주의
min_particles / max_particles위치 후보 particle 수 범위많으면 계산량 증가, 적으면 복잡한 환경에서 표현력 부족
update_min_d이 거리만큼 이동해야 filter 갱신작으면 자주 갱신, 크면 위치 반영 지연
update_min_a이 각도만큼 회전해야 갱신작으면 계산 증가, 크면 회전 반영 지연
laser_max_rangeLocalization에 사용할 최대 scan 거리실제 LiDAR 범위와 환경을 넘겨 설정하지 않음
alpha1~alpha5odometry motion noise model임의 조정보다 실제 motion·encoder 오차를 근거로 튜닝
transform_tolerance발행 TF의 시간 여유근본적인 clock·network 지연을 숨기지 않음

초기 위치가 틀리거나 map→odom TF가 불안정한 문제를 particle 수만 늘려 해결하려 하지 않습니다. 먼저 Map·Scan 정합, laser frame, odometry, timestamp를 봅니다.

ros2 param list /amcl
ros2 param get /amcl min_particles
ros2 topic echo /amcl_pose --once
ros2 run tf2_ros tf2_echo map odom
07

Controller·속도·목표 허용 오차

Controller plugin에 따라 DWB, Regulated Pure Pursuit(RPP) 등 파라미터 이름이 달라집니다. 먼저 현재 plugin과 전체 parameter list를 확인합니다.

ros2 param list /controller_server
ros2 param dump /controller_server --output-dir ~/robot_param_backup
계열대표 이름효과·주의
최대 속도max_vel_x, max_linear_vel낮추면 안전하고 안정적, 높이면 추종 오차·제동거리 증가
최대 회전max_vel_theta, max_angular_vel높으면 빠르지만 scan·Localization 불안정 가능
가속도acc_lim_x, acc_lim_theta실제 motor가 따라갈 수 있는 범위 사용
목표 허용 오차xy_goal_tolerance, yaw_goal_tolerance작으면 정밀하지만 목표 주변 진동·실패 가능
RPP lookaheadlookahead_dist길면 부드럽지만 급곡선 둔감, 짧으면 민감·진동 가능
Goal checkerstateful위치 도달 후 방향 정렬 상태 처리 방식에 영향
이름이 없을 때: 다른 Controller plugin을 쓰는 것입니다. 인터넷 예제 이름을 그대로 만들지 말고 ros2 param list와 실제 YAML의 plugin namespace를 기준으로 찾습니다.

SLAM은 모두 RQT로 바뀌지 않는다

구성주요 설정 위치RQT 변경
SLAM ToolboxROS parameter YAML노출·동적 지원 항목만 가능
CartographerLua configuration·launch argument많은 algorithm option은 재시작 필요
Map SaverCLI·Map Saver parameter저장 시점·파일 옵션 중심

지도 왜곡은 parameter 이전에 주행 속도, wheel slip, LiDAR 가림, odometry, TF, loop closure 경로를 먼저 확인합니다.

# 공통 입력 점검
ros2 topic hz /scan
ros2 topic hz /odom
ros2 run tf2_ros tf2_echo odom base_link

# Simulation이면 clock도 확인
ros2 topic echo /clock --once
